# Checkout SDK review fix

## Code fix included
- PaymentDone listener now uses a sessionStorage lock so duplicate PaymentDone/remounts do not spam CheckoutSDK.checkTransaction.
- checkTransaction is delayed briefly and called once per PaymentDone/order.
- No automatic SDK polling is used. The payment-result page only polls the merchant backend.

## Before submitting Zalo review
The reviewer message says the Mini App did not record a payment through Checkout SDK. A source-code fix cannot convert Sandbox transactions into Production transactions.

For the backend deployed on Render, verify the production merchant configuration supplied by Zalo and set:

PAYMENT_ENVIRONMENT=production
PAYMENT_PRIVATE_KEY=<production private key from Zalo Checkout merchant configuration>

Then redeploy the backend and create a fresh order in the Zalo app. The production method IDs generated by this source are COD and ZALOPAY. Sandbox uses COD_SANDBOX / ZALOPAY_SANDBOX.

Do not repeatedly press/reopen Checkout during one test; checkTransaction is rate limited by the SDK.
